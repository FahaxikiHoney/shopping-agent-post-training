# Contributing

Thanks for helping improve this first public version. Questions, bug reports, documentation fixes, reproducibility notes, and code contributions are welcome.

## Before opening an issue

- Search existing issues to avoid duplicates.
- Include the project version/commit, operating system, Python/CUDA versions when relevant, exact command, and a short sanitized error excerpt.
- Never attach API keys, `.env` files, model weights, private logs, customer or user data, personal addresses, or order identifiers.
- For training/evaluation results, state the dataset split, model identifier, seed, and relevant config. Do not claim a result is reproducible unless you have rerun it.

## Proposing a change

1. Open an issue first for large changes so the direction can be discussed.
2. Fork the repository and create a focused branch.
3. Keep changes scoped; update the relevant docs and examples when behavior or commands change.
4. Run the checks relevant to your change and include the commands and results in the pull request. Do not add large checkpoints or generated run outputs.
5. Open a pull request describing the motivation, changes, validation, and any data/licensing implications.

## Data and model contributions

Do not submit datasets, prompts, logs, or model outputs unless you have the right to redistribute them and have removed personal, confidential, and credential data. Include source, license, collection/creation method, intended use, and known limitations in the pull request. A code license does not automatically license contributed data or model weights.

By submitting a contribution, you agree that it may be distributed under this repository's MIT license for code, unless the contribution is clearly marked otherwise and the maintainers agree before merging. Dataset licensing must be handled separately and explicitly.

Please follow the [Code of Conduct](CODE_OF_CONDUCT.md).
