# Mock 结构化商品属性优化设计

## 目标

保持真实 `sku_recall` 返回契约不变，增强 Mock 商品内部属性生成、商品名投影和候选约束校验，使模型能够仅根据真实可见字段验证用户的核心要求。

## 约束

- 不新增真实工具契约不存在的返回字段。
- 不直接把完整 Query 伪装成商品属性。
- 不针对单个样本写死商品。
- 不追求所有 Query 均有商品，保留合理空召回。
- 主召回和场景召回使用一致的核心约束判断。

## 设计

### 属性解析

从多语言 Query 中解析可验证的核心约束，包括价格上下限、屏幕尺寸区间、床品尺寸、BTU、容量、功率、刷新率、颜色、材质和明确功能词。解析结果只表示用户要求，不直接证明商品满足要求。

### 属性生成

Query 层商品不再只生成 `Standard/Choice/Plus` 空壳名称。按品类和约束生成三个具有合理差异的候选属性；明确的硬约束必须被满足，软属性可以形成档位差异。无法可靠生成的长尾类别仍可空召回。

### 契约投影

将模型需要验证的少量关键属性写入 `sku_name`，其余返回字段保持真实契约：`sku_id`、`sku_name`、`brand_name`、`final_price`、`price`、`img_url`、`good`、`sales`、`keyword`。

### 约束过滤

候选输出前检查价格、尺寸、BTU、容量、功率、刷新率、颜色、材质和子品类。字段无法证明满足硬约束时，不返回或不允许展示。场景召回不得绕过该检查。

## 错误处理

- 无法可靠解析单位时不虚构精确规格。
- 约束之间冲突时返回空结果。
- 价格、尺寸等硬约束无法满足时保留安全空召回。
- 不使用 `keyword` 与原 Query 相同作为商品满足约束的证据。

## 验证

- 保持工具契约和确定性测试通过。
- 新增价格、电视尺寸、BTU、床品尺寸、刷新率、材质和类别冲突测试。
- 验证主召回和场景召回均不能输出违反硬约束的候选。
- 运行现有全量测试，并对固定 100 条中的约束型样本做回归审计。
